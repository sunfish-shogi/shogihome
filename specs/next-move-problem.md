# 次の一手問題集（作成・出題機能）

解析済み棋譜ファイルから悪手（勝率が大きく下降した指し手）を検出し、その直前の局面を「次の一手」問題として収録した問題集を作成する機能と、問題集を使って出題・解答する機能を提供する。

問題集ファイルのデータフォーマットは [next-move-problem-format.md](./next-move-problem-format.md) で定義する。

## 対応プラットフォーム

- **問題集の作成**: Electron 版のみ。ローカルディレクトリの走査と USI エンジンによる再探索が必要なため。
- **出題**: Electron 版・Web 版の両方。問題集ファイル（JSON）を読み込めれば動作する。ただし出典棋譜を開く機能は Electron 版のみ。
- **モバイル版 Web アプリ**: 出題に対応する。モバイル専用の全画面出題ダイアログを使用する（[出題画面](#出題画面) 参照）。

## 問題集の作成

### 概要

1. 指定されたローカルディレクトリから棋譜ファイルを列挙する。
2. 各棋譜の解析コメントから評価値を抽出して勝率に換算し、悪手候補（勝率が閾値以上下降した指し手）を列挙する。
3. 悪手候補の直前の局面を USI エンジンの MultiPV で再探索し、最善手と次善手以下の候補手を求める。
4. 採用条件を満たした局面を問題として収録し、JSON ファイルに保存する。採用した問題が 1 問もない場合はファイルを作成せず、その旨をメッセージで表示する。

### 対象ファイル

- 指定ディレクトリ直下、およびサブディレクトリを再帰的に走査する。
- 対象は ShogiHome が対応する棋譜形式（KIF / KIFU / KI2 / KI2U / CSA / JKF）とする。
- 読み込みに失敗したファイル、解析コメントを含まないファイルはスキップし、件数をサマリーで報告する。
- 分岐（変化手順）は対象とせず、本譜のみを走査する。

### 評価値の抽出と勝率換算

- 既存の解析コメント解釈処理（`parseComment`）を使用する。ShogiHome 形式のほか、Floodgate・ShogiGUI・K-Shogi などの形式も対象となる。
- 同じ局面に検討由来（`researchInfo`）と対局者由来（`playerSearchInfo`）の両方の評価値がある場合は検討由来を優先する。
- 評価値のないノードや詰み宣言のみのノードは悪手判定の対象外とする。
- 悪手判定・採用判定はすべて**勝率（%）**で行う。評価値から勝率への換算は棋譜解析機能と同じ `scoreToPercentage`（アプリ設定の `coefficientInSigmoid` を使用）を用いる。これにより、評価値そのものではなく「勝勢／劣勢」といった局面の重要度に即した判定になる。

### 採用条件

指し手の直前局面・直後局面の**手番側から見た勝率**を `winRateBefore`、`winRateAfter`（%）とする。

以下の条件をすべて満たす指し手を問題として採用する。判定はすべて手番側から見た勝率（%）で行う。

**検出条件：**

- 手数が `minPly` 以上 `maxPly` 以下であること。
- `winRateBefore >= minWinRate` であること。**手番側がすでに劣勢な局面は対象外とする**（上界は設けない）。優勢な局面での悪手（勝ちを逃した局面）は重要である一方、劣勢からの逆転は相手依存で重要度が低いため、上界と下界は対称に扱わない。
- `winRateBefore - winRateAfter >= winRateDropThreshold` であること（手番側から見て勝率が閾値ポイント以上下降）。
- 対局者の条件（下記「設定項目」の対局者）に一致する側の指し手であること。

**再探索・採用判定：**

- その指し手の**直前の局面**を USI エンジンで MultiPV 再探索する。
  - `MultiPV` オプションに設定値（2 以上）を指定する。
  - 1 局面あたりの探索時間は設定値（秒）で打ち切る。
  - 探索結果から MultiPV の候補手（指し手・評価値・読み筋・深さ）を取得する。
- 最善手が実戦の手と異なること。
- すでに逆転困難な局面でないこと。**最善手を指しても手番側の勝率が `minWinRate` を下回る場合は不採用とする**（検出条件と同じ下限を用いる非対称なフィルタ）。
- 最善手と実戦の手の勝率差が `adoptionWinRateDiff` 以上であること。実戦の手の評価値は、MultiPV 候補に実戦の手が含まれる場合はその値を、含まれない場合は棋譜解析コメントの値を使用する。
- 正解が絞り込めること。最善手との勝率差が `acceptableWinRateDiff` 以内の候補手は正解（`accepted: true`）として扱うが、MultiPV のすべての候補が正解となる場合（どの手を指しても大差ない場合）は問題として不採用とする。
- 同一局面（SFEN の手数を除いた部分が一致）の問題が既に採用されていないこと。

採用した問題が `maxProblems` に達した時点で処理を打ち切る。

### 設定項目

| 項目                   | 既定値 | 説明                                                    |
| ---------------------- | ------ | ------------------------------------------------------- |
| 棋譜ディレクトリ       | (なし) | 走査対象のディレクトリ。必須                            |
| 対局者                 | 全て   | 全て / 先手のみ / 後手のみ / 対局者名で絞り込み         |
| 対局者名               | (なし) | 「対局者名で絞り込み」選択時のみ。部分一致              |
| 開始手数 (`minPly`)    | 20     | この手数より前の指し手は対象外                          |
| 終了手数 (`maxPly`)    | 120    | この手数より後の指し手は対象外                          |
| 勝率降下幅             | 20 %   | `winRateDropThreshold`。検出対象とする勝率下降の最小値  |
| 対象局面評価の下限     | 40 %   | `minWinRate`。劣勢・逆転困難な局面の除外に使用          |
| エンジン               | (なし) | 再探索に使用する USI エンジン。必須                     |
| MultiPV                | 3      | 再探索時の候補手の数。2 以上                            |
| 1 局面あたりの探索時間 | 10 秒  | 再探索の打ち切り時間                                    |
| 採用判定の勝率差       | 15 %   | `adoptionWinRateDiff`。採用に必要な最善手と実戦の手の差 |
| 正解範囲の勝率差       | 5 %    | `acceptableWinRateDiff`。複数の正解を認める範囲         |
| 問題数の上限           | 100    | `maxProblems`                                           |
| 出力ファイル           | (なし) | 保存先の JSON ファイルパス。必須。拡張子は `.json`      |

### 進捗表示と中断

- 処理中は進捗（処理済みファイル数 / 総ファイル数、再探索済み局面数 / 悪手候補数、採用済み問題数）を表示する。
- ユーザーはいつでも中断できる。中断した場合、それまでに採用した問題を保存するか破棄するかを選択できる。
- 完了時にサマリー（対象ファイル数、スキップしたファイル数、悪手候補数、採用した問題数）を表示し、保存した問題集の出題をそのまま開始するかどうかを確認する。

## 出題

### 開始と終了

- メニューから問題集ファイル（JSON）を開くと出題モードに入る。問題集の作成完了時にそのまま開始することもできる。
- `format` フィールドが `"shogihome-next-move"` でないファイル、`version` が未知のファイルはエラーとする。
- 出題モードを終了すると元の棋譜表示に戻る。セッション（出題順・成績・現在の問題）は破棄されず保持される。
- セッション保持中にメニューから問題集を開こうとすると「前回の続きから再開しますか？」と確認し、再開するか別の問題集を開くかを選択できる。
- セッションは別の問題集を開くか、新しい問題集を作成して出題を開始したときに置き換えられる。アプリを終了すると消える（永続化は将来拡張）。

### 出題順

- 「順番どおり」と「ランダム」を選択できる。
- 「次の問題」「前の問題」で問題間を移動できる。未解答のままのスキップも可能とする。

### 出題画面

- 出題局面を盤面に表示し、解答側の手番であることを明示する。
- 問題に直前の指し手（`previousMove`）が記録されている場合は、盤面の最終手として強調表示する。
- 盤面の向きは解答側が手前になるように自動で反転する（手動での反転も可能）。
- 解答前は候補手・評価値・実戦の手・読み筋を表示しない。
- 出典（棋譜ファイルのパス・対局者名）の表示は解答後に行う。
- モバイル版 Web アプリでは全画面のモバイル専用ダイアログを使用する。表示内容・操作はデスクトップ版と同等とするが、
  盤面は画面サイズに応じて縦型またはコンパクトレイアウトで表示し、出典棋譜を開くボタンは表示しない（Web 版のため）。

### 解答と判定

- 解答は盤上で駒を動かして行う。合法手のみ受け付ける。
- 指した手は盤面に反映され、局面が進んだ状態で判定結果をメッセージボックスで表示する。
  - `accepted: true` の候補手に一致 → **正解**のメッセージを表示し、結果表示に進む。
  - 実戦の手に一致 → **不正解**。「実戦で指された手」であることを併せて表示する。
  - それ以外 → **不正解**。
- 不正解の場合はもう一度チャレンジするかどうかを確認する。
  - 再挑戦する場合は出題局面に戻して解答を受け付ける。
  - 再挑戦しない場合は出題局面に戻して結果表示に進む。
- 「答えを見る」で解答を打ち切って結果表示に進むこともできる。

### 結果表示

解答後（または「答えを見る」の後）に以下を表示する。

- 候補手の一覧と評価値（正解の手を強調表示）。
- 実戦の手と評価値。
- 各候補手の読み筋。選択した候補の読み筋（相手の応手を含む）を盤上で再生できる。
- 出典棋譜の情報。Electron 版では「棋譜を開く」ボタンで出典棋譜ファイルを開ける（ファイルが存在しない場合はエラーメッセージを表示し、出題は継続する）。棋譜を開くと出題ダイアログは閉じるが、セッションは保持されるためメニューから再開できる。

### 成績

- セッション中の成績（解答数・正解数・正解率）を表示する。
- 成績は出題モードを終了しても保持され、再開時に引き継がれる。セッションが置き換えられるとリセットされる。ファイルへの永続化は行わない（将来拡張）。

## 実装メモ

- 問題集の型定義とフォーマットの読み書き（バリデーション含む）は `common/` に配置し、renderer / background の両方から利用できるようにする。
- 棋譜ファイルの列挙と読み込みは background で行い、既存の IPC パターン（`bridge.ts` / `api.ts`）に従って renderer に提供する。
- 再探索は既存の USI セッション管理を利用し、解析機能（`AnalysisManager`）と同様に renderer 側のストアで進行を管理する。
- 生成設定は `common/settings/` の他の設定（`BookImportSettings`、`AnalysisSettings` 等）と同じパターン（default / normalize / validate）で定義し、アプリ設定として保存・復元する。

## 将来拡張（本仕様のスコープ外）

- 成績の永続化と問題ごとの正解履歴の記録（間隔反復学習への応用）。
- 詰みが絡む局面（評価値ではなく詰み手数が記録された局面）の問題化。
- 複数の問題集のマージ、問題の手動追加・削除・編集。
- 問題へのタグ付けと絞り込み出題。
