# 棋譜分岐ツリー表示

棋譜の分岐構造をツリーとして可視化する機能の仕様と実装プラン。

## 概要

- 棋譜ペインの表示を切り替えると、棋譜リストの右側(現在は思考時間・コメントの列)が分岐ツリーの表示になる。
- ツリーの各ノードの Y 座標は左側の棋譜リストの行(手数)と対応する。つまり ply が同じノードは、リストのその手数の行と同じ高さに描画される。
- 棋譜リストとツリーは同一のコンテナ内で一緒に縦スクロールする。
- ツリーは分岐が増えるほど横に広がるため、ツリー部分のみ横スクロールできる。横スクロール時も棋譜リストは左端に固定される。
- ツリーは左寄せで、分岐が増えるほど右下に枝が広がる。本譜(メインライン)が常に最も左のレーンを占める。
- ノードはドット(円)、アーク(親子間の接続)は線分で表す。
- 現在のノードと、選択中のライン(アクティブ分岐)上のすべてのアークは強調表示する。

## スコープ

- 第 1 段階: ツリーの表示(実装済み)。
- 第 2 段階: ノードのホバーによるツールチップ表示と、クリックによるノードへの移動(実装済み)。
- コンテキストメニューなどの追加のアクションは今後の拡張とする。

## 表示仕様

### レイアウト

- ツリーは「レーン」(横方向の列)と「ply」(縦方向の行)のグリッド上に配置する。
  - Y 座標 = ply × 行高。行高は棋譜リストの行(`.move-element` の 1.4em / font-size 0.85em)と同じ em 基準で算出し、フォントスケールの変更に追従する。
  - X 座標 = レーン番号 × レーン幅(固定値)。
- レーン割り当て:
  - ルート(開始局面, ply 0)から DFS で走査する。`next` で連なる一続きのノード列を「ライン」として扱い、ラインごとにレーンを割り当てる。
  - 本譜のラインはレーン 0。
  - 分岐ライン(`branch` でたどる弟ノードから始まるライン)は、区間 [分岐元の ply, ラインの終端 ply] が既存の配置と重ならない最も左のレーンを選ぶ(貪欲な区間パッキング)。ただし分岐元のレーンより左には置かない。区間が重ならなければ複数の分岐ラインが同じレーンを共有する。
  - 同一ライン上に複数の分岐点がある場合は深い分岐点から順に処理する。これにより、浅い分岐点からのアークが先に配置された縦線をまたぎにくくなる。同じノードからの複数の分岐は、分岐リストの並び順(先頭が左)に配置する。
- アーク:
  - ライン内の連続するノード間: 同一レーン上の縦線分。
  - 分岐点: 親ノード (ply p, lane Lp) から分岐ライン先頭ノード (ply p+1, lane Lc) への斜め線分。将来折れ線に変更できるよう描画側で吸収する。
- ツリーの全体サイズはレーン数 × 最大 ply から決まる。分岐側のラインがアクティブラインより長い場合、ツリーの高さはリストよりも大きくなり得る。

### 強調表示

- 現在のノード(`record.current`): ドットを大きく・強調色で描画する。
- アクティブライン(`activeBranch` を根から順にたどった経路)上のアーク: 太い線・強調色で描画する。両端のノードがともにアクティブライン上にある辺が対象。
- その他のノード・アークは標準色・細線で描画する。
- 色は既存の CSS 変数(`--text-color`, `--text-bg-color-selected` など)を基準に定義する。

### ノードの装飾

- コメントがあるノードは右下に小さなダイヤを表示する。ダイヤは `--text-bg-color-selected` で塗り、`--text-color` で縁取る。ノード(丸)と区別しやすいよう角のある形にする。
- しおり(ブックマーク)があるノードは右上に小さな星印を表示する。星は `--text-bg-color-warning` で塗り、`--text-color` で縁取る。
- どちらのマークも同一レーンの縦のアークと接触しないよう x 方向に余白を取る。

### スクロール

- 縦スクロールは「棋譜リスト列」と「ツリー列」を含む外側のコンテナ(`.move-list.with-tree`)が単一で担う。列とツリーは同じ縦スクロール領域内の横並び要素なので、常に一緒に動く。JavaScript による縦スクロール同期は不要。
- 横スクロールはツリー列専用の入れ子コンテナ(`.tree-scroll`)だけが持つ。棋譜リスト列はこのコンテナの外にある通常配置の要素であり、横スクロールの影響を受けない。
  - `position: sticky` は使わない。棋譜リスト列とツリーの横スクロール領域を最初から別要素にすることで、横スクロール時にツリーが列の下へ物理的に潜り込むことがなくなる。
  - これにより、半透明表示(`opacity`)を使っていても、ツリーが列を透けて見えたり、列の背景だけ不透明度が二重に合成されて濃く見えたりする問題が発生しない(半透明レイヤーは論理的に「隠す」のではなく「透過させる」ものであり、重ねても完全な遮蔽にはならないため、列とツリーを画面上で重ねないことが根本対策になる)。
- 既存の「選択行への自動縦スクロール」に加え、現在のノードが見えるように `.tree-scroll` の `scrollLeft` を自動追従させる。

### ツールチップ

- ノードにマウスを乗せると、ノードの近くにツールチップを表示する。
- 表示内容は「手数・指し手」「消費時間(開始局面では非表示)」「しおり(存在する場合のみ)」「コメント(存在する場合のみ)」。
- コメントは最大 4 行で省略し、文字も小さめにして画面レイアウトを破綻させない。
- スクロールコンテナにクリップされないよう `position: fixed` で表示する。
- 左右方向は画面端にかかる場合にノードの反対側へ反転する。
- 上下方向はノードが表示エリア(スクロールコンテナ)の上半分にあれば下側、下半分にあれば上側に表示し、エリアの下端でツールチップがはみ出さないようにする。

### クリック操作

- ノードをクリックするとそのノードへ移動する(tsshogi の `gotoNode` を使用)。
- 現在の経路と異なるノードの場合は、分岐の切り替えを伴って合流点から先へ進んだ状態になる。
- 棋譜が操作可能な状態(`AppState.NORMAL`)でのみ有効。

### 表示切り替え

- 棋譜表示下部のオプション行(消費時間・コメントのトグルと同じ場所)に「分岐ツリー」のトグルを追加する。
- ツリー表示中は思考時間・コメントの列を表示しない(トグル自体は非表示にする)。
- 下部の分岐リスト(候補一覧)は第 1 段階ではそのまま残す。ツリー上のクリック操作が実装された後に整理を検討する。
- 標準レイアウト・モバイルレイアウトでは `AppSettings.showBranchTreeInRecordView: boolean`(既定値 false)として永続化する。
- カスタムレイアウトでは、この設定はアプリ全体の設定ではなく、レイアウトプロファイルの棋譜コンポーネントごとに `showBranchTree?: boolean` として保持する(`showCommentColumn` / `showElapsedTimeColumn` / `branches` と同様)。カスタムレイアウトの棋譜ペインは下部のオプション行自体を表示しないため、切り替えはレイアウトマネージャー(カスタムレイアウト編集画面)の棋譜コンポーネントのプロパティから行う。

## 実装プラン

### 1. レイアウト計算モジュール(純粋 TypeScript・テスト可能)

`src/renderer/helpers/recordTreeLayout.ts`

```ts
export type RecordTreeNode = {
  id: number; // 描画用の連番 ID(Vue の key)
  node: ImmutableNode; // tsshogi ノードへの参照(拡張用)
  ply: number; // 縦位置
  lane: number; // 横位置
  onActiveLine: boolean;
  current: boolean;
};

export type RecordTreeEdge = {
  from: { ply: number; lane: number };
  to: { ply: number; lane: number };
  onActiveLine: boolean;
};

export type RecordTreeLayout = {
  nodes: RecordTreeNode[];
  edges: RecordTreeEdge[];
  laneCount: number;
  maxPly: number;
};

export function buildRecordTreeLayout(record: ImmutableRecord): RecordTreeLayout;
```

- `record.first` から `next` / `branch` をたどって全ノードを走査する。
- 座標は「レーン番号 × ply」の論理座標のみを返し、px/em への変換は描画側で行う。
- ノードごとに `node` への参照を保持し、コメント・ブックマーク・指し手情報による将来の色分けやツールチップに備える。

### 2. 描画コンポーネント

`src/renderer/view/primitive/RecordBranchTree.vue`

- props: `record: ImmutableRecord`(+必要なら透過度など)。
- `computed` で `buildRecordTreeLayout` を呼び、1 枚の SVG に描画する。
- ノードは `circle`、アークは `line`。強調は class + CSS 変数で表現する。
- emits:
  - `clickNode: [node: ImmutableNode]` — RecordView → RecordPane を経由して `store.changeNode`(`Record.gotoNode`)に接続する。
  - `hoverNode: [node: ImmutableNode | null]` — 追加の拡張用。ツールチップ自体はコンポーネント内で表示する。
  - ヒット領域はドットより大きめの透明要素として用意する。

### 3. RecordView への組み込み

`src/renderer/view/primitive/RecordView.vue`

- `showBranchTree` prop と `toggleShowBranchTree` emit を追加(既存の `showElapsedTime` / `showComment` と同じパターン)。
- ツリー表示時の DOM 構造:

```
.move-list-area(overflow: auto ← 縦横)
  .move-list-content(width: max-content; min-width: 100%)
    .row
      .move-list-column(sticky; left: 0; 背景あり)  ← 手数 + 指し手
      RecordBranchTree                               ← SVG
```

- 通常表示時は現状の構造・挙動を一切変えない。
- `onUpdated` の自動スクロール処理にツリーの横方向追従を追加する。

### 4. RecordPane / 設定 / i18n

- `src/common/settings/app.ts`: `showBranchTreeInRecordView: boolean` を追加(既定 false、normalize 対応)。
- `src/renderer/view/main/RecordPane.vue`: appSettings から prop を渡し、トグルの emit で `updateAppSettings` を呼ぶ(既存トグルと同じ経路)。StandardLayout / MobileLayout / CustomLayout は RecordPane 経由のため個別対応は不要。
- i18n: `ja.ts` / `en.ts` に「ツリー」(例: `tree`)を追加。`zh_tw.ts` / `vi.ts` は翻訳ポリシーに従い `// TODO: Translate` を付けて日本語のまま追加する。

### 5. テスト

`src/tests/renderer/helpers/recordTreeLayout.spec.ts`

- `createMoveByUSI` と `Record.append` で分岐入りの棋譜を構築してレイアウト結果を検証する。
- ケース:
  - 分岐なし(レーン 0 のみ)
  - 単一分岐(分岐ラインがレーン 1 に載る、分岐アークが生成される)
  - ネストした分岐(分岐の中の分岐が右のレーンに載る)
  - 同一ノードからの 3 つ以上の分岐
  - 分岐側のラインがアクティブラインより長いケース(maxPly が伸びる)
  - 区間が重ならない分岐同士のレーン再利用
  - アクティブライン切り替え時の `onActiveLine` / `current` の反映
- コンポーネントは既存の view テストのパターンに従い、ノード・アーク数と強調 class を確認する最小限のマウントテストを追加する。

### 6. 動作確認

- `npm run serve` で分岐入り棋譜(KIF)を読み込み、以下を確認する:
  - リストとツリーの行の高さが一致し、一緒に縦スクロールすること
  - 横スクロールでリストが固定されること
  - 分岐の切り替え(下部の分岐リスト)で強調表示が追従すること
  - フォントサイズ変更・画面リサイズへの追従
- `npm run lint` / `npm test` を通す。

## パフォーマンスに関する補足

- レイアウト計算は record 変更ごとに O(全ノード数)。定跡編集などで生じる数千ノード規模でも SVG 直描画で問題ない見込み。
- それを超える規模が問題になった場合は、可視 ply 範囲のみを描画する仮想化を導入する。
